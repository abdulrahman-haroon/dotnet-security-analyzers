# DSA001: Endpoint has no authorization

| | |
|---|---|
| Severity | Warning |
| Category | Security |
| Maps to | [OWASP Top 10:2021 A01 Broken Access Control](https://owasp.org/Top10/A01_2021-Broken_Access_Control/), [CWE-862 Missing Authorization](https://cwe.mitre.org/data/definitions/862.html) |

## What it finds

An endpoint that doesn't say who may call it:

**Controllers:** a public action with no authorization attribute on the action, the controller, or any base controller. These count as authorization:
- `[Authorize]` / `[AllowAnonymous]`, and anything implementing `IAuthorizeData` or `IAllowAnonymous` (e.g. a class deriving from `AuthorizeAttribute`),
- an attribute that is an authorization filter (implements `IAuthorizationFilter` or `IAsyncAuthorizationFilter`),
- a filter attribute whose name contains *Authoriz*, *Permission* or *Access*, e.g. `[AuthorizeAdmin] : TypeFilterAttribute` or `[CheckPermission]`. The filter such attributes wrap can't be inspected from a compiled library, so the name is used.

**Minimal APIs:** `MapGet` / `MapPost` / `MapPut` / `MapDelete` / `MapPatch` / `MapMethods` / `Map` with none of:
- `.RequireAuthorization()` or `.AllowAnonymous()` on the endpoint,
- `[Authorize]` or `[AllowAnonymous]` on the handler lambda or method,
- a route group that requires authorization, e.g. `app.MapGroup("/api").RequireAuthorization()`. Nested groups and `group.RequireAuthorization();` as a separate statement are understood too.

## Why it matters

In ASP.NET Core, endpoints are **public by default**. Forget `[Authorize]` on one controller or one `MapPost`, and anyone can call it. This is the most common access-control bug in real APIs.

## Example

```csharp
[ApiController]
public class AccountsController : ControllerBase
{
    [HttpGet("{id}/balance")]
    public IActionResult GetBalance(int id) => ...;          // DSA001
}

app.MapPost("/api/transfer", (decimal amount) => ...);     // DSA001
```

## How to fix

**Quick fix (lightbulb / Ctrl+.):** *Add [Authorize] to this action*, *Add [Authorize] to the controller*, or *Add [AllowAnonymous]*. On a minimal API endpoint: *Add .RequireAuthorization()* or *Add .AllowAnonymous()*. Each can be applied to the whole document, project or solution with **Fix all**.

Say who may call it:

```csharp
[Authorize]
public class AccountsController : ControllerBase { ... }

app.MapPost("/api/transfer", ...).RequireAuthorization();

var api = app.MapGroup("/api").RequireAuthorization();    // everything in the group
```

If an endpoint is meant to be public, say so explicitly:

```csharp
[AllowAnonymous]
public IActionResult Health() => Ok();

app.MapGet("/health", () => "ok").AllowAnonymous();
```

## App-wide protection is recognised

The rule stays silent when the app protects endpoints globally:

| Setup | Silences |
|-------|----------|
| `options.FallbackPolicy = ...` or `AddAuthorizationBuilder().SetFallbackPolicy(...)` | controllers **and** minimal APIs |
| `options.Filters.Add(new AuthorizeFilter())` (global MVC filter) | controllers only |
| `app.MapControllers().RequireAuthorization()` | controllers only |

## When the rule stays silent on purpose

To avoid false alarms, DSA001 does **not** warn when it can't see the whole picture:
- the endpoint builder is stored in a variable or returned (`var e = app.MapGet(...)`),
- endpoints are mapped on a parameter, field or helper method result, e.g. inside `static void MapOrders(this IEndpointRouteBuilder routes)`. The caller may pass a group that is already protected.

## Limits

- Global protection is detected by name (`FallbackPolicy`, `SetFallbackPolicy`, `AuthorizeFilter`, `RequireAuthorization` after `MapControllers`). Protection set up in a way that doesn't use these names isn't seen. If so, turn the rule off in `.editorconfig`:
  ```ini
  [*.cs]
  dotnet_diagnostic.DSA001.severity = none
  ```
- Razor Pages and SignalR hubs are not checked.
