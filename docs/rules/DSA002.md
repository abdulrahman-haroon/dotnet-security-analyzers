# DSA002: CORS policy allows any origin with credentials

| | |
|---|---|
| Severity | Warning |
| Category | Security |
| Maps to | [OWASP Top 10:2021 A05 Security Misconfiguration](https://owasp.org/Top10/A05_2021-Security_Misconfiguration/), [CWE-942 Permissive Cross-domain Policy with Untrusted Domains](https://cwe.mitre.org/data/definitions/942.html) |

## What it finds

A CORS policy that calls `SetIsOriginAllowed` with a function that always returns `true`, **and** calls `AllowCredentials()` in the same policy.

## Why it matters

ASP.NET Core refuses `AllowAnyOrigin()` together with `AllowCredentials()` and throws when the policy is built, because the combination is dangerous. `SetIsOriginAllowed(_ => true)` is the common workaround found online. It switches the check off: the server echoes back whatever `Origin` the browser sends, with `Access-Control-Allow-Credentials: true`.

The result: **any website** a logged-in user visits can call your API with the user's cookies and read the response.

## Example

```csharp
builder.Services.AddCors(o => o.AddPolicy("spa", p =>
    p.SetIsOriginAllowed(_ => true)      // DSA002
     .AllowCredentials()));
```

## How to fix

List the sites you trust:

```csharp
builder.Services.AddCors(o => o.AddPolicy("spa", p =>
    p.WithOrigins("https://app.example.com")
     .AllowCredentials()));
```

Load the list from configuration if it changes per environment.

## Not flagged

- `SetIsOriginAllowed(_ => true)` **without** `AllowCredentials()`: a public, cookie-free API may legitimately accept any origin.
- `SetIsOriginAllowed(origin => ...)` with a real check.

## Limits

The rule looks for `AllowCredentials()` in the same lambda or method that calls `SetIsOriginAllowed`. A policy built across several methods is missed.
