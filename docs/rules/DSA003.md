# DSA003: JWT signing key is hardcoded

| | |
|---|---|
| Severity | Warning |
| Category | Security |
| Maps to | [OWASP Top 10:2021 A02 Cryptographic Failures](https://owasp.org/Top10/A02_2021-Cryptographic_Failures/), [CWE-321 Use of Hard-coded Cryptographic Key](https://cwe.mitre.org/data/definitions/321.html) |

## What it finds

A `SymmetricSecurityKey` (from `Microsoft.IdentityModel.Tokens`) created from a value written in the code:

```csharp
new SymmetricSecurityKey(Encoding.UTF8.GetBytes("my-secret"))     // string literal
new SymmetricSecurityKey(Encoding.UTF8.GetBytes(SomeConst))       // const string
new SymmetricSecurityKey(Convert.FromBase64String("c2VjcmV0"))    // base64 literal
new SymmetricSecurityKey(new byte[] { 1, 2, 3 })                  // byte array literal
new SymmetricSecurityKey("my-secret"u8.ToArray())                 // UTF-8 literal
```

It also follows the value back through **local variables and `readonly` fields** declared in the same file, as long as they are never assigned again:

```csharp
private static readonly string Key = "my-secret";
...
var bytes = Encoding.UTF8.GetBytes(Key);
new SymmetricSecurityKey(bytes)                                   // DSA003
```

## Why it matters

This key signs and checks your JWTs. Anyone who has it can create a token for **any user with any role**. A key in the source code is in git history forever, in every clone, and inside the compiled DLL, where anyone can read it with a decompiler.

## How to fix

Read the key from configuration that is backed by a secret store:

```csharp
var key = builder.Configuration["Jwt:SigningKey"]
    ?? throw new InvalidOperationException("Jwt:SigningKey is not configured.");
var signingKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(key));
```

- Development: `dotnet user-secrets set "Jwt:SigningKey" "<value>"`
- Production: Azure Key Vault, AWS Secrets Manager, or an environment variable set by your platform.

If the key was ever committed, **rotate it**. Deleting it from the code does not remove it from git history.

## Limits

- Values defined in **another file**, in a non-readonly field, or in a property are not followed.
- A variable that is assigned again anywhere in its method (e.g. `if (prod) key = config["Jwt:Key"];`) is deliberately not followed, to avoid false alarms.
- Keys in `appsettings.json` are not checked. Use a secret scanner such as GitHub secret scanning or gitleaks as well.
