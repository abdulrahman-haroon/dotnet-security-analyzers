# DSA004: Developer exception page is not limited to Development

| | |
|---|---|
| Severity | Warning |
| Category | Security |
| Maps to | [OWASP Top 10:2021 A05 Security Misconfiguration](https://owasp.org/Top10/A05_2021-Security_Misconfiguration/), [CWE-209 Generation of Error Message Containing Sensitive Information](https://cwe.mitre.org/data/definitions/209.html) |

## What it finds

A call to `UseDeveloperExceptionPage()` that is not inside an `IsDevelopment()` check.

## Why it matters

The developer exception page shows the full stack trace, source code lines, query string, headers and cookies of the failing request. In production, anyone who can trigger an error sees how your app is built, and sometimes secrets.

## Example

```csharp
var app = builder.Build();
app.UseDeveloperExceptionPage();          // DSA004: also runs in production
```

## How to fix

Since .NET 6, `WebApplication` **already enables** the developer exception page in the Development environment. The usual fix is to delete the line and add a production error handler:

```csharp
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/error");
    app.UseHsts();
}
```

If you need the explicit call (older `Startup` style), guard it:

```csharp
if (env.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
}
```

## Recognised as safe

- Inside `if (x.IsDevelopment())` or `if (x.IsEnvironment("Development"))`, including `&&` conditions.
- In the `else` of `if (!x.IsDevelopment())`.
- In either branch of `?:` with the same rules.
- Inside `Startup.ConfigureDevelopment(...)`, which ASP.NET Core only calls in Development.

## Limits

An early exit above the call, e.g. `if (!env.IsDevelopment()) return;`, is not recognised. Wrap the call in an `if` instead, or suppress the warning on that line with a comment saying why.
