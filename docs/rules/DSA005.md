# DSA005: Security cookie is weakened

| | |
|---|---|
| Severity | Warning |
| Category | Security |
| Maps to | [OWASP Top 10:2021 A05 Security Misconfiguration](https://owasp.org/Top10/A05_2021-Security_Misconfiguration/), [CWE-614 Sensitive Cookie in HTTPS Session Without 'Secure' Attribute](https://cwe.mitre.org/data/definitions/614.html), [CWE-1004 Sensitive Cookie Without 'HttpOnly' Flag](https://cwe.mitre.org/data/definitions/1004.html) |

## What it finds

On a `CookieBuilder`, the object behind the **authentication, session and antiforgery cookies** (`options.Cookie` in `AddCookie`, `AddSession`, `AddAntiforgery`, ...):
- `SecurePolicy = CookieSecurePolicy.None`: the cookie is also sent over plain HTTP.
- `HttpOnly = false`: JavaScript on the page can read the cookie.

## Why it matters

These cookies **are** the user's login. Sent over HTTP, anyone on the same network (café Wi-Fi, a proxy) can copy it. Readable by JavaScript, any XSS bug can steal it. Either way, the attacker becomes the user.

## Example

```csharp
builder.Services.AddSession(o =>
{
    o.Cookie.HttpOnly = false;                            // DSA005
    o.Cookie.SecurePolicy = CookieSecurePolicy.None;      // DSA005
});
```

## How to fix

**Quick fix (lightbulb / Ctrl+.):** *Set HttpOnly = true* / *Set SecurePolicy = CookieSecurePolicy.Always*.

Delete these lines: the defaults are safe (`HttpOnly = true`). Better still, require HTTPS explicitly:

```csharp
o.Cookie.HttpOnly = true;
o.Cookie.SecurePolicy = CookieSecurePolicy.Always;
```

## Not flagged

- Cookies written with `Response.Cookies.Append(..., new CookieOptions { ... })`. These are often harmless (a theme preference that JavaScript reads on purpose). Microsoft's CA5382 / CA5383 check their `Secure` flag; see the README for how to enable them.
- `CookieSecurePolicy.SameAsRequest` (the default for some cookies). It is safe when the whole site is HTTPS.
