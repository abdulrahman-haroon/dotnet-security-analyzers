# DSA008: Sensitive data written to the log

| | |
|---|---|
| Severity | Warning |
| Category | Security |
| Maps to | [OWASP Top 10:2021 A09 Security Logging and Monitoring Failures](https://owasp.org/Top10/A09_2021-Security_Logging_and_Monitoring_Failures/), [CWE-532 Insertion of Sensitive Information into Log File](https://cwe.mitre.org/data/definitions/532.html) |

## What it finds

A `string` variable, parameter, field or property passed to `ILogger.Log*` (as an argument, interpolation or concatenation) whose name ends in `password`, `passwd`, `clientSecret`, `secretKey`, `apiKey`, `privateKey`, `accessToken`, `refreshToken`, `idToken`, `cardNumber` or `cvv`:

```csharp
logger.LogInformation("Login {User} {Password}", user, password);   // DSA008
```

## Why it matters

Logs are copied to other systems, read by more people and kept for a long time.

## How to fix

Leave the value out:

```csharp
logger.LogInformation("Login {User}", user);
```

No automatic fix: only you know what the message needs.

## Not flagged

- Values passed through a method (`Mask(password)`), or non-strings (`hasPassword`, `password.Length`).
- Names that only contain the word (`passwordHash`, `tokenExpiry`).
- Code inside an `IsDevelopment()` check, and test projects.

## Limits

- Name-based: a secret in a variable called `value` is missed.
- `[LoggerMessage]` methods and other logging libraries' own APIs are not checked.
